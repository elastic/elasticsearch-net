# RequestConverter.Wasm

A WebAssembly build of the Elasticsearch .NET request converter. It wraps
[`RequestConverter.Convert`](../RequestConverter/RequestConverter.cs) and exposes two
JavaScript-callable entry points (`Exporter.Check` / `Exporter.Convert`) that satisfy the external
exporter protocol of the [`@elastic/request-converter`](https://github.com/elastic/request-converter)
host. This lets the .NET converter run in the browser and produce C# client code live.

## Protocol

The module follows the host's `ExternalExporter` contract (plain JSON in and out):

- `check(input)` - input `{"requests": ParsedRequest[]}`; output `{"return": <bool>, "error"?: "..."}`.
- `convert(input)` - input `{"requests": ParsedRequest[], "options": ConvertOptions}`; output
  `{"return": <string>, "error"?: "..."}`.

Field names are snake_case. `options.type_name_style` (`Simplified` | `Fqn` | `GlobalFqn`) selects
how type names are spelled in the generated code; it maps to the library's
[`TypeNameStyle`](../RequestConverter/FormattingOptions.cs). A request the converter does not support
(for example an NDJSON `bulk`) makes `check` return `false` and `convert` return an `error`.

`options.syntax_mode` (`object_initializer` | `descriptor`, default `object_initializer`) selects the
emitted syntax; it maps to the library's [`SyntaxMode`](../RequestConverter/FormattingOptions.cs).
`object_initializer` emits object initializers (`new SearchRequest { Query = ... }`); `descriptor`
emits the fluent descriptor chain (`new SearchRequestDescriptor().Query(q => q.Match(...))`). It pairs
with `use_strongly_typed_document`: when set, descriptor mode emits the generic
`XDescriptor<DocumentTypeName>` flavor with `.Field(f => f.Path)` expression lambdas; otherwise the
non-generic descriptor with string field values.

`options.use_strongly_typed_document` (bool) switches field references to
`Infer.Field<DocumentTypeName>(x => x.Path)` lambdas and a generic request's document body to
`new DocumentTypeName { ... }`. `options.document_type_name` (string, default `MyDocument`) sets that
type name. The named type is not generated by the converter; the caller supplies it, so this output is
illustrative and generally does not compile or round-trip as-is. Both map to
[`FormattingOptions`](../RequestConverter/FormattingOptions.cs); omitting them keeps the string/`JsonElement` default.

`options.client_call_format` (`none` | `statement` | `inline`, default `none`) appends the client invocation that
executes the request: `statement` declares the request variable and calls
`var response = await client.Esql.QueryAsync(request);`; `inline` passes the request initializer (object-initializer
mode) or the configuration lambda with hoisted required path arguments (descriptor mode) directly as the call
argument, e.g. `var response = await client.Indices.CreateAsync("my-index", d1 => d1.Settings(...));`.
`options.client_call_style` (`async` | `sync`, default `async`) selects the awaited asynchronous flavor or the
synchronous one. In a batch, request and response variables are suffixed (`request1`/`response1`, ...) so the
snippets can be pasted together.

`ParsedRequest` is produced by the host's parser, not by this module: turning Dev Console text into
the API name and URL parameters needs the Elasticsearch schema, which the host library owns. The
browser harness below shows the full pipeline (parse with the host, convert with this module).

## Error reporting

The `error` string a failed `convert` returns is the whole message the host shows the user, so it is
kept concise and free of stack traces. Failures are classified:

- **Wrong-typed values** report the underlying problem plus a location composed from the JSON path,
  line, and column, e.g. `Unable to convert JSON string value 'abc' to 'Int32'. (at $, line 1, column 14)`.
- **Structurally invalid bodies** (e.g. an array where an object is expected) report the token
  mismatch with a location, e.g. `Expected JSON 'StartObject' token, but got 'StartArray'. (at $, line 1, column 2)`.
- **Unsupported endpoints** report a converter coverage gap naming the request, e.g. `The .NET request
  converter does not yet support the 'xpack.info' endpoint (GET /_xpack).`
- **Bad path/query parameters** and other failures get a clear, endpoint-named message.
- In a **batch**, the message is prefixed with the failing request's index and API.

Set `options.debug` to `true` to append the full exception (type + stack trace) after a
`--- debug ---` marker for diagnosing unexpected failures.

`check` is a yes/no probe: any request that cannot be converted (unsupported endpoint, invalid body,
...) makes it return `false` rather than an error.

Notes on what does not surface as an error:

- **Malformed JSON** never reaches this module: the host parses the request body before sending, so the
  body is always well-formed JSON by the time it arrives here.
- **Unknown properties** are ignored: the client deserializer skips unmapped members (the
  System.Text.Json default), so a typo'd or extra property is dropped silently rather than reported.
- **Missing required properties** are not detected during deserialization, so they surface with a
  generic message (not the specific property name). The precise path/column location and the property
  name would require a change to the client generator's converters, tracked separately.

## Prerequisites

- .NET 10 SDK.
- The `wasm-tools` workload, registered for the .NET 10 SDK band:

  ```
  dotnet workload install wasm-tools
  ```

  A workload installed only through the Visual Studio installer may not be visible to command-line
  builds; if `dotnet build` reports `NETSDK1147: ... wasm-tools`, run the command above.

## Build

```
dotnet publish src/RequestConverter.Wasm/RequestConverter.Wasm.csproj -c Release
```

The runnable AppBundle is written to (this repository redirects build output under `.artifacts`):

```
.artifacts/bin/RequestConverter.Wasm/release_browser-wasm/AppBundle/
```

containing `main.mjs`, `package.json`, and `_framework/` (`dotnet.js`, the runtime, and the managed
assemblies).

The bundle is large (~40 MB uncompressed) because the converter compiles the entire Elasticsearch
client into one assembly and is published untrimmed: it materializes request types by runtime lookup
and reflects over exported types for collision-aware type-name shortening, both of which IL trimming
would break. A static host that serves Brotli-precompressed assets (which the .NET WASM SDK emits)
ships far less over the wire.

## Run the live browser harness

The harness in [`harness/`](harness/) parses Dev Console requests with the published
`@elastic/request-converter` (loaded from a CDN) and converts them with this WASM module wrapped in
the host's `ExternalExporter`, updating as you type.

Serve the repository root over HTTP (WebAssembly will not load from `file://`), then open the
harness. For example, with [`dotnet serve`](https://www.nuget.org/packages/dotnet-serve):

```
dotnet tool install --global dotnet-serve     # once
dotnet serve -d .                              # from the repository root
```

Then browse to:

```
http://localhost:8080/src/RequestConverter.Wasm/harness/
```

Any static server works (`npx serve`, `python -m http.server`, etc.); serve from the repository root
so the harness's default relative path to the AppBundle resolves. The AppBundle path is editable in
the page if you serve from elsewhere.

Type a request such as:

```
POST /my-index/_search
{ "query": { "match_all": {} } }
```

and the generated C# updates live. Switch the type-name style to compare `Simplified`, `Fqn`, and
`GlobalFqn` output.

## Use from Node

`main.mjs` also boots under Node. Import its `boot()` factory to get `{ check, convert }`:

```js
import { pathToFileURL } from "node:url";
const { boot } = await import(
  pathToFileURL(".artifacts/bin/RequestConverter.Wasm/release_browser-wasm/AppBundle/main.mjs").href
);
const { check, convert } = await boot();

const request = {
  api: "search",
  path: "/my-index/_search",
  raw_path: "/my-index/_search",
  method: "POST",
  url: "/my-index/_search",
  source: "POST /my-index/_search\n{ \"query\": { \"match_all\": {} } }",
  body: { query: { match_all: {} } },
};

const result = JSON.parse(convert(JSON.stringify({ requests: [request], options: {} })));
console.log(result.return);
```

Running `node main.mjs <check|convert> <jsonPayload>` directly invokes the named entry point and
prints its JSON result, which is convenient for ad-hoc testing.
